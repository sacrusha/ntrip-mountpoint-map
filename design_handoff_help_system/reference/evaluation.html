Correction to v1

My first pass was written from a fresh web-fetch of the text content only and missed how much interactive scaffolding the site already ships. For the record, the following are already present — so the real critique is not "add these," it is "the ones that exist don't read as a coherent product." Features I misattributed as missing:

  • Dark-mode chrome with proper CSS variables for light/dark swap.
  • A Sources filter panel: per-operator checkboxes, access-tier grouping (open · registration · conditions), VRS / Pending / Restricted toggles, out-of-view declutter.
  • A fixed Legend panel with the zone palette and marker types.
  • A first-visit "how it works" mini-guide that auto-opens, plus a full guide modal.
  • Station popup with per-field copy (Server, Port, Mountpoint, Username, Password), accuracy tier, legacy-RTCM warnings, NEAR-mountpoint hint, registration links, and a "Receiver setup guide →" link.
  • Station count, last-updated timestamp, mobile filter FAB with slide-in drawer.

The redesign below treats all of this as given and restructures rather than replaces.

Audience · confirmed

The README, CLAUDE.md, and the guide agree: hobbyists and small shops looking for cm-accurate GPS within ~100 km of a reference station. Not consumers, not ag-tech enterprises.

Real users

Owners of ArduSimple / SparkFun / Emlid / Trimble / Leica / Topcon gear — or people evaluating a purchase from that list. They know what NTRIP is, or are willing to learn from one page. They care about four things, in order:

1. Is there a free station near where I'm working?   2. What are the host / port / mountpoint?   3. What login do I need?   4. Will the stream actually work with my receiver?

Every one of those needs is answered on the site today. The problem is how hard they are to see.

01

Return-visit surveyor

Knows their mountpoint. Reopens the site to double-check credentials or find a backup stream. Wants the fastest path from map to Copy.

02

First-time hobbyist

Bought an ArduSimple kit, opens the map cold. Gets a wall-of-text modal first. Needs a 10-second orientation, then the map.

03

Curious buyer

Deciding whether to invest. Wants to confirm free coverage exists where they work before spending €275–€3,000.

What the site already does well

Acknowledging this up front so the findings below are read as refinements, not a rewrite.

✓ Data & pipeline

  • ~5,500 stations across 65 sources
  • Refreshed 4×/day via GitHub Actions
  • Staleness handling: grey ≥3d, hidden ≥7d
  • Country-level markers for non-ingested networks
  • Static JSON — no third-party proxy

✓ Map engineering

  • Canvas coverage raster at low zoom
  • KDBush spatial index for range queries
  • 3 zoom bands: raster → dots → labels+rects
  • 4-band RTK baseline palette
  • Dark-mode parity via CSS variables

✓ Info architecture

  • Per-field copy on host / port / mountpoint
  • Accuracy tier shown (L1+L2 vs L1-only)
  • Legacy RTCM 2.x warnings in popup
  • NEAR auto-select hint where supported
  • First-visit onboarding + full guide

Revised findings

Reordered and rewritten against what the site actually does. The meta-theme: the UI reads like an admin panel, not a product. Two frosted panels, a blue banner bar, a first-visit modal, and a dense dark map compete for attention on first paint.

01

First paint is overwhelming

Hierarchy · onboarding

A new visitor sees simultaneously: a blue banner strap, a "Learn more" link, a zoom control, the Sources panel with 7+ rows + collapsed Access group, the Legend panel, a busy green-field map, and a full-text "Getting centimetre-accurate GPS" modal opens on top. There's no visual spine telling the eye where to land.

High
02

Two floating panels that overlap in meaning

IA · redundancy

The Sources panel (top-right) shows the coloured swatches per operator. The Legend (bottom-left) shows another palette (zone colours, VRS ring, grey ring, ?-marker, stale-grey). A user scanning the map must jump between opposite corners to decode any pin. Consolidate into a single left rail with Legend ∙ Filter in one surface.

High
03

No product identity at all

Branding

A blue banner strap with a generic message is the entire brand. There's no name in a persistent position, no mark, no hierarchy — which is why the site reads as a Leaflet demo even though it's genuinely the most comprehensive free-RTK directory online. A 44-56px top bar with name + tagline + Guide link costs almost nothing and changes the register completely.

High
04

First-visit modal is long, even if it's only shown once

Onboarding

Noted that this fires first-visit-only (localStorage ntrip-howit-seen) — so returning users aren't hit by it. The remaining issue is that the single shot you get at a new user is five paragraphs of body copy over a map they haven't seen yet. A phased intro (one-sentence framing, two buttons — I'm here for coordinates / Explain RTK in 60 s) respects the time of the technical audience while keeping the full explainer one click away.

Medium
05

Discovery: finding the right station is harder than it should be

Discoverability · core task

This is the one that really matters. The map answers "show me the world of free RTK" well, but the real user task is "is there a usable station where I'll be working, and which one should I connect to?" — and nothing on the page actively helps with that. The user pans, zooms, clicks pins, and eyeballs distance. Five concrete moves, low → high effort:

  1. Place-search field in the top bar. Nominatim / OSM geocoder. Accepts city, postcode, or lat,lon. Zooms the map and drops a transient "you searched here" pin.
  2. "Near me" button using the browser Geolocation API (IP-centre is the cold fallback, not the precise answer). Once positioned, highlight the 3 closest stations in a side panel with distance, tier, and a one-click Copy.
  3. Sort-by-distance side list that appears once a location is known (searched or geolocated). Same data as pins, but as a rankable list: AMPH · 6.2 km · green · Centipede · copy. This is what a surveyor actually wants.
  4. Mountpoint search in the same field — if the user knows they want AMPH, autocomplete it and fly-to. The data is already indexed; surfacing it costs a Fuse.js and a dropdown.
  5. Permalink / URL state — centre, zoom, selected mountpoint, active filters in the hash. Makes stations shareable and lets the site be deep-linked from forum posts ("try this one").

Of these, the top-bar search + Near-me button + ranked nearest list cover ~90% of the discovery gap with one afternoon of work.

High
06

Popup dense but under-structured

Connection flow

The popup does the right things (copy buttons, accuracy tier, NEAR hint, registration link) but the visual rhythm is flat — labels, code, buttons all compete. Monospace the data, constrain label column width, drop a single primary action in the footer ("Copy all as ntrip:// URL" or "Open in Emlid Flow" when detected).

Medium
07

Typography: one system-sans, one size

Visual design

Everything is font-family: sans-serif — meaning every user sees a different rendering (Helvetica, Arial, Segoe UI, Fira). Counts, host values, and station names share the same face as body copy. One editorial face for titles, the existing sans for UI, and a monospace for data (hosts, ports, mountpoints) is enough to remove the "debug page" quality.

Medium
08

Station count + last-updated are tiny

Trust signals

4,585 stations · updated 1h ago in the Legend footer is the trust signal of the site. It deserves to be promoted to the chrome — "6,385 free stations · updated 2 h ago" as a monospace line beside the product name reads as "this is live, maintained data."

Medium
09

Sources panel treats 40+ networks as equal peers

Filter UX

The panel collapses most sources under "Access" but shows 4 named sources at top (Centipede, rtk2go, AUSCORS, SAPOS). A "Near me" virtual group (sources with a station in current viewport) solves the practical need — I don't care about AUSCORS if I'm in Germany.

Low
10

Dense green-on-dark is the default impression

Visual weight

At world/continent zoom the map is a solid field of green circles. This is genuine information — it shows coverage density — but without other colour the eye has nothing to rest on. A slightly lower fill-opacity on the coverage raster and a more restrained pin at mid-zoom would let VRS purple, amber, and pale-red actually register.

Low

Before / after · First screen

Same features. Calmer surface.

The proposal keeps the dark theme, the coverage raster, the legend + filter functionality, and the onboarding. It consolidates the two floating panels into one left rail, moves identity + live stats into a persistent top bar, and defers the long explainer to a dismissible banner + full-guide drawer.

Recommendations · ranked

01 · HIGH

Consolidate Legend + Sources into one left rail

Single surface, top-to-bottom: legend → free stations by operator → network types → declutter. Removes corner-to-corner eye jumping.

02 · HIGH

Add a persistent top bar

Name + live station count + last-updated + search + Guide + "Near me." Turns the page from "map embed" into "product."

03 · HIGH

Address the discovery gap

Top-bar place + mountpoint search, Geolocation “Near me,” and a ranked nearest-station side list once a location is known. Covers the real user task in ~one afternoon.

04 · HIGH

Deep-link state to the URL hash

Centre, zoom, selected mountpoint, active filters. Makes stations shareable on forums and preserves state across reloads.

05 · MED

Rewrite the first-visit modal as a two-choice intro

One sentence + I’m here for coordinates / Explain RTK in 60 s. Full text stays one click away in the guide drawer.

06 · MED

Restructure the station popup

Header (name + tier + distance), monospace kv rows with per-field copy (already there, visually flatten labels), single primary footer action.

07 · MED

Commit to a type system

Editorial serif for titles, workhorse sans for UI, monospace for all data. Removes the "debug panel" impression without changing the palette.

08 · MED

Promote freshness signal

Move 5,472 stations · updated 2h ago out of the legend footer into the top bar. It is the site's main trust signal.

09 · LOW

"In view" source grouping

Auto-promote sources with pins currently visible; demote the rest. Scales better as the catalogue grows past 65 operators.
