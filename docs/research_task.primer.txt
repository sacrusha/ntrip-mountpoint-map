NTRIP RTK research primer. Audience: agents running docs/research_task.txt. Self-contained operational knowledge. Deeper material: docs/gnss-ai-guide.md (load section only if primer insufficient). AI-only file; compression per /caveman skill at level full (see CLAUDE.md).

abbrev: NRTK=Network RTK, VRS=Virtual Ref Station, MAC=Master-Aux Concept, FKP=Flachen-Korrektur-Parameter, SSR=State-Space Repr, OSR=Observation-Space Repr, CORS=Continuously Operating Ref Station, IAR=Integer Ambiguity Resolution, ITRF=Internat Terr Ref Frame, IGS=Internat GNSS Service.

[ntrip]
RTCM corrections over TCP. v2 = HTTP/1.1; v1 = raw TCP, HTTP-shaped request but no Host header, response starts "SOURCETABLE 200 OK" not "HTTP/1.1 200". Many national casters (SAPOS, several others in SOURCES) are v1-only — HTTP clients fail with BadStatusLine; fetch_stations.py falls back to raw socket.
port 2101 = convention only. real port arbitrary: 2001 InaCORS, 5001 LatPos, 8080 NYSNet, 9881 ORGN, 10010 MSRN, 10099 AlCORS, etc. wrong port = silent refusal; published port often firewalled even when service alive.
probe: `curl --http0.9 -A 'NTRIP/1.0' --max-time 8 http://rtk2go.com:2101/`
client flow: GET / -> sourcetable; GET /MOUNTPOINT -> RTCM byte stream. auth = HTTP Basic (base64). shared creds common on open casters (rtk2go any-email/none; Centipede centipede/centipede; MonPOS rover/262461). VRS mounts also need rover to push back NMEA GGA; without GGA = TCP open, zero RTCM.

[sourcetable]
caster index. STR;mountpoint;identifier;format;format-details;carrier;nav-system;network;country;lat;lon;nmea;solution;... (also NET, CAS records, ignored).
fetch_stations.py reads fields: 1=mountpoint, 3=format, 5=carrier, 6=nav-system, 8=country, 9=lat, 10=lon, 11=nmea, 12=solution. accuracy-rectangle uses lat/lon decimal places.
filters applied in pipeline:
  carrier 0 = DGNSS (code-only, multi-metre) -> dropped, out of scope.
  carrier blank + format "RTCM 3*" -> treated as carrier 2 (rtk2go fills carrier sloppily).
  carrier not in {1,2,3} -> dropped invalid.
  nmea=1 -> caster expects rover GGA = VRS/MAC/FKP/iMAX/NEAR; no real coord -> dropped.
  solution=1 -> "network solution" per spec, same meaning -> dropped.
  lat=lon=0 or non-finite -> dropped.
  longitude >180 normalized -360 (ERGNSS reports 353.65 instead of -6.35).
  all coords identical across mountpoints -> whole source dropped as vrs-only (one rounded city centre, not antennas).
operator misconfig common: physical stations mis-tagged nmea=1 or solution=1. fetch_stations.py SOURCES carries per-caster nmea_filter / solution_filter = False overrides (rtk2go, geortk, renep, auscors, igac, icecors, almgg_mn, nps_cors). do NOT infer nrtk presence from nmea/solution flags alone — read sourcetable rows + operator portal.

[nrtk-detection]
operator docs strongly preferred.
sourcetable inspection can confirm nrtk by mountpoint name (ex: *_VRS, *_MAC, *_FKP, *_iMAX, *_NEAR) but NRTK mounts may live invisibly on a second sourcetable on an unknown port. nmea=1 alone is unreliable: misconfigured by operator both directions.

[stations-vs-mps]
mountpoints do not map clean to physical stations:
  multiple streams from one station (RTCM3 + CMR + legacy + MSM-only)
  some casters publish routing aliases (NEAR/AUTO/VRS + variants) in addition to, or instead of, individual stations
  DGNSS mountpoints are not RTK in our sense.

[base-roles]
CORS = continuously operating reference station. real physical RTK base, real-time RTCM via NTRIP.
some networks have both RTK and post-process only (RINEX archive, no real-time RTCM); our station count of RTK networks refers to RTK stations.
single-base RTK mountpoint = 1 CORS, 1 stream. effective up to ~10-30 km. degrades via ppm.
NRTK mountpoint = multi-station synthesis, effective baseline ~0 km inside network hull (<=70 km spacing); degrades fast outside hull (silent extrapolation, dm-m errors, no RTCM warning).

[datum-epoch]
datum = geodetic frame coords expressed in. examples: ETRS89, NAD83(CSRS), GDA2020, CGCS2000, ITRF2014, IGS20, WGS84(Gxxxx).
epoch = date station coords anchored. examples: 2010.0, 2020.0.
why: cross-epoch conversion cm offset per year, cross-datum conversion metre-offset.
plate-fixed national frames (ETRS89, NAD83(CSRS), CGCS2000, SIRGAS2000): tied to continental plate; drift only across plate boundaries.
global realizations (ITRFyyyy, IGSyy, WGS84(Gxxxx)): used by international casters (EarthScope NOTA, IGS, BKG).
semi-dynamic (AU GDA2020 @ 2020.0, NZ NZGD2000 @ 2000.0): publish velocity model; cm-accurate transform needs coord + per-station velocity.
operational citation rule (also in research_task.txt): only operator portal/spec/decree citable. declared only, not inferred. no operator declaration -> omit.
some networks have a few stations running on their own datum & epoch, usually older or geographically distinct — don't stop datum-epoch research early.

[national-portals]
national casters AUSCORS and MIRAI also rebroadcast select international stations, rarely primary outside main regions.

[licensing]
known types:
  CC BY / national-survey-free  AU, NZ, most EU national CORS, BR, CO     yes; citation on publications
  NULA-style non-commercial     EarthScope NOTA                            yes for personal; no for paid work (landscaper-for-pay -> not free)
  volunteer-pool implicit       rtk2go, community Centipede                yes; "use freely don't abuse"
  restricted / paid             Gulf-state networks, some DE Lander tiers  no

[accuracy]
RTK acc = fixed_mm + (ppm * baseline_km). typical hobbyist hardware (Emlid RS2+, ZED-F9P + survey antenna): 7mm + 1ppm.
@10km ~17mm. @30km ~37mm. >30km single-base = marginal.
VRS inside hull (<=70km station spacing) ~0km effective baseline -> ~7-8mm regardless of nearest physical station. outside hull = silent extrapolation, dm-m errors, no warning.
relevance to research: single-base CORS 30+km from user = marginal. NRTK with <=70km spacing = good throughout hull. note when operator publishes baseline guidance.
